## What is the vulnerability?

Drupal 7.108 fixes two security issues:

- **Restored cache hardening (CVE-2024-55638):** This release restores the `DrupalCacheArray::__destruct()` hardening from [SA-CORE-2024-008](https://www.drupal.org/sa-core-2024-008), which was lost in Drupal 7.103.
- **External authentication access bypass (no CVE assigned):** Case-insensitive matching of external authentication names could allow an access bypass. Drupal now accepts only an exact match for names stored in the `authmap` table, and refuses new external logins whose name differs from an existing account only by case or trailing spaces.

## Are sites on Pantheon affected?

Yes. Drupal 7 sites running a version before 7.108 are affected until you update.

## What Pantheon has done

Pantheon provides Drupal 7.108 as an upstream update through [long-term support for Drupal 7](/supported-drupal/#drupal-7-long-term-support) with Tag1 Consulting.

## What you need to do

1. Apply the latest upstream update to your Drupal 7 site. See [how to apply core updates](/core-updates#apply-upstream-updates-via-the-site-dashboard).
1. Run database updates in each environment, either from `update.php` or with Terminus:

   ```bash{promptUser: user}
   terminus drush $site.$env -- updatedb
   ```

The release includes the `user_update_7021()` database update, which makes the `authmap.authname` column case-sensitive on MySQL. The update stops without making changes if your `authmap` table contains names that differ only by case or trailing spaces. If that happens, merge or remove the duplicate entries, then run database updates again.

If your site uses an external authentication module, such as SAML, LDAP, or OpenID, confirm that your identity provider sends names with consistent casing. Otherwise, affected users might see "Unable to log in. Contact the site administrator."
