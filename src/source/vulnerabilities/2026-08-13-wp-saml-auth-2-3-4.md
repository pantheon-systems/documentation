## What is the vulnerability?

In WP SAML Auth 2.3.2 and earlier, an accent-insensitive database collation could match a SAML attribute to the wrong WordPress user, which allows an account takeover. User lookup is now verified with a case-insensitive, accent-sensitive comparison.

Version 2.3.3, released on August 11, 2026, contained this fix, but the package published to the WordPress Plugin Repository was missing its `vendor` directory, which includes the bundled `onelogin/php-saml` library. Sites that took that update couldn't authenticate through SAML. Version 2.3.4 corrects the packaging and carries the security fix.

## Are sites on Pantheon affected?

[WP SAML Auth](https://wordpress.org/plugins/wp-saml-auth/) is a Pantheon-maintained plugin that you install on your site. It isn't part of the Pantheon platform. Your site is affected if it runs the plugin:

- **2.3.2 or earlier:** The site is missing the security fix.
- **2.3.3 from the WordPress Plugin Repository:** The site has the security fix but might be unable to authenticate through SAML.
- **Composer installs:** Sites that install the plugin with Composer aren't affected by the packaging issue, because `onelogin/php-saml` is resolved as a dependency. They should still update if they run 2.3.2 or earlier.

## What Pantheon has done

Pantheon released WP SAML Auth 2.3.3 with the security fix, and 2.3.4 the following day to correct the packaging.

## What you need to do

Update to 2.3.4 as soon as possible from the WordPress dashboard under **Plugins > Installed Plugins**, or download it from the [WordPress Plugin Repository](https://wordpress.org/plugins/wp-saml-auth/).
